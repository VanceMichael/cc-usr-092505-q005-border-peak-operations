# 口岸高峰勤务编排

哈尔滨机场边检双节高峰的值守计划后端核心：把**航班版本、预计/实际旅客量、入出境方向、通道与智能设备能力、人员资质、班次与休息约束、应急预留**统一排进时段值守计划；计划发布后以事件修订未执行时段，并在交班时给出同一读取水位的值守摘要。

全部逻辑为仓库内纯 JavaScript，无网络、无数据库、**不接入真实机场设备**；时间取自可注入时钟，自动化用例可用固定航班与时钟确定性重放一次完整高峰。

## 业务规则

- **通道随流开放**：按航班压力窗投影出每时段入/出境的自助与人工旅客量，据此增开通道；自助通道能力不足（设备停用）或旅客不适用自助（证件异常）时，压力转人工，人工仍消化不了的人数排队并结转到下一时段。
- **资质门槛**：人工查验岗须持 `manual-inspection`，自助监管岗须持 `smart-supervision`，加急协查岗须持 `urgent-cooperation`；另有入/出境方向授权。不具备资质或方向授权的警力不会被排到该岗位，换岗同样被拒。
- **班次与休息**：跨午夜班次（如 20:00–次日 02:00）以线性墙钟分钟计算；连续执勤达上限后强制休息，由其他警力顶岗，无可用警力则记缺口。
- **应急预留**：预备警力默认保持预留；加急协查优先动用预留警力，预留不足时才借调一线，仍不足产生预留缺口。
- **只修订未执行时段**：事件（航班改时、设备停用、岗位换班、加急协查、证件异常）重排时，已开始时段的通道安排、协查派警、缺口与交接记录原样冻结保留。
- **并发争用**：事件携带计划版本与资源版本（航班/人员/通道/设备/案件），两个调度员争用同一人员或通道时，基于过期版本的较晚提交被拒绝；事件 `eventId`、航班 `updateId` 幂等，重复提交回放原结果。
- **证件材料授权**：航班与计划中只保留证件异常人数；材料明细存于授权文档库，值班长与协查角色可见，其他角色（如航班保障）只见案件编号。
- **交班摘要同一水位**：正在开放的通道、在岗协查、下一时段缺口与队列结转、临时调整依据、未处理异常，都在 `(nowIso, planVersion, eventSeq)` 同一读取水位上生成。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/time.js` | ISO 墙钟分钟、跨午夜班次日程、30 分钟时段网格 |
| `src/clock.js` | 可注入/可推进时钟（`advance`/`jumpTo`，不可回拨） |
| `src/flights.js` | 航班版本流（乐观版本 + `updateId` 幂等）、压力窗投影、峰值 |
| `src/scheduler.js` | 编排器：通道开放、资质/方向/班次/休息、预留、冻结与换岗锁定 |
| `src/documents.js` | 证件材料授权库（按角色裁剪明细） |
| `src/service.js` | `PeakService`：发布、事件账本、并发拒绝、重排冻结、队列积压、交班摘要 |
| `src/index.js` | 模块桶导出 |

## 事件类型

提交入口：`service.submitEvent(event)`。

- `flight-update`：航班改时/预计或实际客流（`expectedFlightVersion` + `updateId`）
- `doc-anomaly`：证件异常人数（转人工）并登记授权材料
- `device-outage`：智能设备停用区间，未执行时段改排
- `shift-change`：人员班次调整（仅未执行时段生效）
- `post-swap`：岗位换班，校验资质/方向/班次并锁定接替者，保留交接记录
- `urgent-case`：加急协案件，优先动用应急预留
- `resolve-anomaly`：异常处理闭环

并发字段：`expectedVersion`（计划版本）、`resourceVersions`（`lane:*`/`officer:*`/`device:*`/`flight:*`/`case:*`）。

## 资料与契约

- `contracts/domain.schema.json`：领域资料结构（沿用）。
- `contracts/peak-service.schema.json`：高峰场景输入契约（窗口、航班、通道、设备、警力、授权材料）。
- `fixtures/domain.json`：领域事实示例。
- `fixtures/peak-scenario.json`：2026 双节跨午夜（20:00–次日 02:00）固定场景，全部虚构。
- `fixtures/replay-script.json`：固定事件脚本，测试与演示共用同一事实来源。

## 开发命令

- 运行测试：`npm test`
- 语法构建：`npm run build`（只做 `node --check`，不连任何外部服务）
- 固定高峰重放演示：`npm run replay`

`npm run replay` 用固定时钟逐水位打印发布、事件接受/拒绝、开放通道、下一时段缺口与队列结转、授权材料可见性；同一脚本重复运行结果逐字节一致（由 `test/replay.test.js` 守护）。
